Passo a passo para o desenvolvimento do desafio técnico:

Requisitos:
- Aplicação de console
- Ler argumentos: ação Preçomin preçomax
- ter um arquivo conf, que possui as configurações de acesso do servidor SMTP
	- Utilizar Yaml para facilitar o desenvolvimento
	- colocar as credenciais em um .env para não expor as Keys no repositório publico
	- Yaml deve ter:
		- endereço das conexões do servidor SMTP
		- o tipo de conexão a ser usada WebSocket ou HttpClient
		- o tempo entre os requests da aplicação

- Monitorar continuamente o preço da ação:
	- Deve-se ter uma thread ou task em background após a inicialização do programa para a cada intervalo de tempo buscar o preço atual 	da ação (pooling por praticidade)
	- e possível no arquivo de configuração setar de quanto em quanto tempo deve se fazer um request para pegar um preço da ação
- Caso o valor da ação Bata em algum limite enviar um alerta para utilizando as configurações do servidor SMTP que ira enviar o email

Modularização do código:
- Classe Logger: para trackear possives erros e logs no console
- Classe Monitor: vai rodar a thread em background, configurações de API, e requests
- Classe ConfRead: vai ler o arquivo conf e salvar os dados na inicialização.
- Classe Alarm: vai checar para ver se o ultimo valor requerido precisa ou não acionar um email.
- classe UserData: vai receber os dados da linha de comando, Yaml e .env, para as outras classes conseguirem fazer o gerenciamento necessario.

- Iterface: IMonitor: interface criada para gerenciar que tipo de requisição e monitoramento usuario quer fazer baseado no tipo de API que ele quer usar, se e via websocket ou HttpClient


Por falta de tempo e pela complexidade baixa implementar utilizando:
- function factory
- Singletons
- Service layers são ideai para projetos grande no caso de um protótipo como esse não e necessário

utilizando o Gemini como auxilio para pegar exemplos de código e exemplos de API
